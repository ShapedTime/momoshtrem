# momoshtrem · Direction B (Playful cat-forward) · handoff notes

This folder is the complete design for Direction B: identity, design system, every screen at 390 / 768 / 1440 px in light and dark, and three clickable flows. The screens are a working, responsive HTML prototype built on the same tokens the Next.js app will use, so the measurements, wrapping and breakpoints you see are the real ones.

- **Open the hub:** `index.html` (brand, system, screen viewer, prototypes). Any static server works: `npx serve docs/redesign/design/playful`.
- **Open the app prototype directly:** `app.html#/for-you`. URL options: `?theme=light|dark`, `&safe=1` (simulated iPhone safe areas), `&flow=1|2|3` (guided flows), `&motion=reduce`.
- **Static exports:** `exports/*.png` (every screen and state at 390 and 1440, key screens at 768, key screens in dark).

| Mascot | Keep the name **Momo** (the first half of momoshtrem). Six poses plus an avatar. Momo speaks in the third person and never in errors that matter. |

## 2. Tokens → `web/`

Files in `tokens/` are generated by `node tools/build-tokens.mjs` from `tools/tokens.source.mjs` (edit the source, not the output).

- `theme.css`: Tailwind v4 CSS-first theme. It resets Tailwind’s default colours and breakpoints so only system tokens exist, adds a `dark:` variant bound to `data-theme="dark"`, and defines dark values in `@layer base`.
- `tokens.css`: the same variables as plain CSS (used by the prototype).
- `tokens.json`: for anything else (docs, tests).
- `CONTRAST.md`: every text/background pair, both themes; all pass AA.

```css
/* web/src/app/globals.css */
@import "tailwindcss";
@import "./theme.css";            /* copy of tokens/theme.css */
```

Utilities you get: `bg-bg`, `bg-surface`, `bg-surface-2`, `bg-raised`, `text-ink`, `text-ink-2`, `text-ink-3`, `border-line`, `bg-primary text-on-primary`, `bg-primary-soft text-primary-soft-ink`, `bg-ready-bg text-ready`, `bg-review-bg text-review`, `text-title-1`, `text-caption`, `font-display`, `rounded-lg`, `rounded-pill`, `shadow-2`, `shadow-lip`, `ease-spring`, `blur-glass`, breakpoints `tablet:` (640) `laptop:` (1024) `desktop:` (1440).

**Fonts with `next/font`:** the font tokens read `var(--font-fredoka, "Fredoka")` and so on, so `next/font` just sets those variables:

```ts
// web/src/app/fonts.ts
import { Fredoka, Atkinson_Hyperlegible_Next, Atkinson_Hyperlegible_Mono } from 'next/font/google';
export const fredoka = Fredoka({ subsets: ['latin', 'latin-ext'], variable: '--font-fredoka', display: 'swap' });
export const atkinson = Atkinson_Hyperlegible_Next({ subsets: ['latin', 'latin-ext'], variable: '--font-atkinson', display: 'swap' });
export const atkinsonMono = Atkinson_Hyperlegible_Mono({ subsets: ['latin', 'latin-ext'], variable: '--font-atkinson-mono', display: 'swap' });
// layout.tsx: <html className={`${fredoka.variable} ${atkinson.variable} ${atkinsonMono.variable}`} data-theme=…>
```

Verify the exact export names against the installed `next/font/google` (Atkinson Hyperlegible Next and Mono were added to Google Fonts in 2025). `latin-ext` is needed for “Shōgun”.

**Theme without a flash:** render `data-theme` from a cookie on the server, or inline a tiny script in `<head>` that sets it from `localStorage`/`prefers-color-scheme` before paint. Settings → App offers System / Light / Dark.

**Reduced motion:** honour `prefers-reduced-motion`, and also `data-motion="reduce" | "full"` on `<html>` from Settings → App. The token file already swaps `--ease-spring` for `--ease-out` and zeroes `--duration-celebrate`; components swap slides for fades (see §6).

## 3. Layout grid

| Range | Columns | Gutter (page margin) | Notes |
|---|---|---|---|
| < 640 (phone, designed at 390) | 4 | 16 px (fluid `clamp(16px, 2.5vw, 40px)`) | Posters 3-up, 12 px gaps. Tab bar 64 px + safe area. Large titles. Sheets come from the bottom. |
| 640–1023 (tablet, 768) | 8 | 24 px | Posters 4–5-up. Still the tab bar. Detail pages single column, bigger hero. |
| ≥ 1024 (laptop/desktop, designed at 1440) | 12 | 40 px, max content 1360 | Top bar 68 px. Detail: content + 384 px sticky side column. Sheets become dialogs. |

- Poster grids are fluid: `repeat(auto-fill, minmax(clamp(104px, 28vw, 172px), 1fr))`. No fixed card widths inside fixed tracks.
- Shelves (horizontal rows) show a peek of the next card, have arrow buttons from 640 up (not hover-only) and an edge fade.
- No horizontal page scroll from 320 px up (checked on every screen with `scrollWidth <= innerWidth`).
- Touch targets ≥ 44 px. Small visual controls (36 px buttons, chips) keep an invisible 44 px hit area via `::after`.

## 5. Screens: what each one must do

1. **Sign in.** `<form method="post" action="/api/auth">` with `username` (`autocomplete="username"`, `autocapitalize="none"`, `spellcheck="false"`) and `password` (`autocomplete="current-password"`), show/hide toggle. Momo peeks over the card and closes its eyes while the password field has focus. Errors: one calm banner + field state; rate limit shows a countdown and disables only the button.
2. **For You.** Greeting + “N episodes ready for tonight”. Ask momoshtrem bar with 2–3 example chips. Up next (landscape cards with availability and the matching action). New episodes for your shows (list). 4–6 AI shelves, each item with a one-line reason and a ⋯ for like / dislike / not interested / already seen (and Add to library). Trakt watchlist. Footer: model, time and cost of the last run, Refresh now. States: Trakt not connected (connect card + trending shelves, clearly “not personal yet”), refreshing (banner with paw track; old shelves stay until new ones land), first time (checklist).
3. **Ask momoshtrem.** Phone: full-screen chat, composer pinned to the bottom (above the safe area), no tab bar. Desktop: thread rail + conversation. While working: the user message, then Momo (detective) with paw steps that stream in (“Reading your history…”, “Searching the web for new releases…”, “Checking TMDB…”), and skeleton cards. Results: Momo’s one-paragraph take, cards (poster, meta, reason, Add to library → Find a torrent, like, dislike, ⋯), refine chips (each is just a follow-up message). The research steps collapse into “Researched in 38 s · 6 web searches · $0.09”.
4. **Discover.** Mood cards; filters (type, several genres, year range, rating, runtime, language + Anime toggle, status) in a left column on desktop and a bottom sheet on phone; active filters as removable chips; sort; infinite scroll with skeletons. **All filter state is in the URL.** Empty result names the filters and offers to drop one.
5. **Search.** Phone: its own tab, list results. Desktop: grid results and the ⌘K palette (titles, your library, actions). Tabs: All / Movies / Shows / In library. Matches original titles (“Sousou no Frieren”). No-results suggests a spelling and offers Ask.
6. **Movie detail.** Hero (backdrop fading into the page, poster, title, year, runtime, rating, genres, director, your Trakt state, trailer). On phone only the poster overlaps the art; text always sits on the page colour. The **availability card** is the one primary action and walks Add → Find a torrent → Downloading (ring, speed, “streams while it downloads”) → Ready in Infuse (How to play + WebDAV path to copy). Then current torrent (name, chips, size, health, Replace) and subtitles (languages, search OpenSubtitles ranked by release match). Desktop: these sit in a sticky right column above the fold.
7. **Show detail.** Same hero. Up next card first. Needs-review banner when a job waits. Seasons as tabs incl. **Specials**. Season header with counts and bulk actions (Find missing (N), Season pack). Long seasons: compact rows, **watched episodes collapse** into one row, ranges (1–12, 13–24, 25–38), jump-to-episode; 1,000+ episode anime use **arcs** (select + chips) and pages of 40, newest first. Show settings sheet: ordering (Aired / Absolute / TMDB episode group), include specials, matching mode, re-run mapping.
8. **Torrent search.** Opens from a movie, season or episode, pre-filled (“Frieren S01E29”) with “Also searched: …”. Scope: Episode · Season pack · Any. **Fixed height** (full-height sheet on phone, 1120 × 860 dialog on desktop), so it never jumps. Sticky query + scope + chips. Best match card with a “why” line. Results show the release name (wrap rule below), attribute chips, size, seeders/leechers, age, indexer, warnings, and Inspect / copy magnet / Add. “Showing 8 of 143 · Load more”. Facets with counts (left column on desktop, nested sheet on phone). States: searching (per-indexer chips), no results (try season pack / original title), partial failure (named indexers + Retry), filters hide everything (names the filters, one-tap remove). **Query, scope and filters survive close and reopen.** Never horizontal scroll.
9. **Mapping review.** Progress (paw steps: Fetching metadata → Matching files → Asking AI about the tricky ones). Groups: Matched · Needs review · Specials · Extras & ignored · Unmatched, as tabs with counts. Row: file name (mono, wraps), size, → target episode button (opens the picker), confidence (3 bars + word), reason (“AI” badge when it came from the model). Conflicts are paired with “Keep this one”. Footer: Re-check with AI (hint field + chips like “these are absolute numbers”), and **Apply N mappings** (N counts only what is resolved; unresolved items are named, never silently applied). Desktop adds a right pane: the season’s episodes and what will play on each (in library / from this torrent / conflict). Applied: proud Momo, list of what’s ready, Open show / Back to For You.
10. **Library.** Search within, sort, grid/list, filters with counts (All · Movies · Shows · Watching · Ready · Incomplete · Needs review). Cards show ready/total, watched progress and download/review state without hover. ⋯ menu: Open, How to play, Find a torrent, **Remove…** (last, red, confirms, offers “also delete data”, toast with Undo).
11. **Activity.** Totals (↓ ↑, what’s happening, speed sparkline). Sections: Streaming now, Downloading, Waiting for you (mapping review), Idle (“loads when Infuse opens a file”). Every torrent links to its title; pause/resume inline. Detail: progress, stats, Pause / Copy magnet / Remove…, files with their mapping, and a collapsed **Advanced** section (piece map with the playhead window, active readers, peers, hash). Backend offline: clear, calm error with the container to check.
12. **Settings.** Sections: Integrations (Trakt: not connected → device code + trakt.tv/activate + expiry → waiting → first sync with paw steps → connected with username, last sync, counts, Sync now, Disconnect…), AI (nightly picks on/off, schedule, model, spend this month split by feature, budget, classifier, auto-apply), Quality profile (preferred resolution, max GB/h with a worked example, prefer x265/HDR/DV, avoid terms, preferred groups), Playback (WebDAV address to copy + 3-step Infuse setup), System status (backend, DB, Jackett with indexer health, TMDB, Trakt, AI, WebDAV), App (theme, motion, Log out).
13. **System states.** See the “System states” screen and the component section of the hub: skeletons, empty states, errors, toasts, confirmation dialog, progress.

## 6. Interaction details

**Long text (exact rule).** Release names and file paths are rendered with a break opportunity (`<wbr>`) after `.` `_` `-` `/` `]` `)` and before `[` `(`, plus `overflow-wrap: anywhere` as the last resort for a single huge token (a hash). So lines only break between tokens. Release rows clamp to 3 lines on phone and 2 on desktop (almost every scene name fits), and the full name is always in Inspect. The parsed title + episode part (“Severance.S02E05”) is bold ink; the rest is ink 2. Titles under posters: 2 lines then ellipsis. Episode titles in rows: 1 line then ellipsis; the episode number and state never truncate. Paths are mono. Helper: `breakable()` in `assets/js/ui.js`.

**Sheets.** Phone: slide up 420 ms (`--ease-sheet`), grabber + close button, drag down past ~30 % or a downward flick dismisses, tapping the scrim dismisses, the body scrolls with `overscroll-behavior: contain`, the header (and the search block in torrent search) is sticky, the footer is sticky. Full-height sheets keep their height while loading. Nested sheets (Filters, Inspect, Episode picker) stack above with a back arrow. Desktop: centred dialog (760 px; 1120 px for torrent search) or side panel. Esc closes the top layer; focus is trapped and returned to the opener. Sheets are routed (`?sheet=`), so Back closes them.

**Sticky things.** Top bar (glass + 18 px blur) and tab bar always. Detail pages: the side column sticks on desktop. Mapping review: the Apply bar sticks to the bottom; the episodes pane sticks on desktop. Discover: the filter column sticks on desktop. Large phone titles scroll away with the page.

**Loading choreography.** Skeletons occupy the final layout boxes, so nothing shifts. Torrent search: per-indexer chips flip to ✓ as each answers; 4 skeleton cards hold the space; results replace them in one go. Ask: paw steps appear one by one; cards rise with a 50 ms stagger when they arrive. Mapping job: three paw steps, then the groups. Trakt: waiting (peeking Momo, paw track) → first sync (paw steps with counts). Polling pauses when the tab is hidden.

**Feedback.** Toasts at the bottom (above the tab bar on phone, bottom-right on desktop), 4 s, with Undo where it’s reversible. Big moments (all mapped, fresh picks) use the proud pose and a tail flick. Destructive actions are visually secondary, live in menus, confirm, and say what stays.

**Keyboard.** ⌘K / Ctrl-K opens the palette anywhere (↑ ↓ to move, ↵ to open, Esc to close). Esc closes sheets, menus and dialogs. Tab order follows reading order; every control has a visible 3 px focus ring.

**Motion and its reduced variant.**

| Motion | Default | Reduced |
|---|---|---|
| Buttons press, chips, toggles | 90–150 ms, scale/translate | colour change only |
| Cat ears on the active tab | spring up 220 ms | appear instantly |
| Sheet open/close | slide 420 ms | 160 ms fade |
| Dialog, palette, toast | pop / drop with spring | 160 ms fade |
| Content arriving (cards, shelves) | rise 12 px, 320 ms, 50 ms stagger | 160 ms fade, no stagger |
| Skeleton shimmer | 1.4 s loop | static |
| Momo loops (z’s, peeking, searching, dots) | gentle loops | single still frame |
| Success (all mapped, picks ready) | proud pose pops, tail flicks twice | still pose |

## 7. Accessibility

- Contrast: every token pair passes WCAG AA in both themes (`tokens/CONTRAST.md`). Status colours always come with an icon and a word; colours that must be told apart also differ in lightness.
- Focus: visible 3 px ring (`--color-focus`) with 2 px offset on every interactive element.
- Targets ≥ 44 px; nothing important is hover-only (posters keep titles visible; actions live in visible ⋯ buttons).
- Real `<button>`, `<a href>`, `<input>` + `<label>` everywhere; icon-only buttons have `aria-label`; live regions for toasts, Ask progress and search status; dialogs use `aria-modal` and return focus.
- Mascot SVGs have `role="img"` and a label; decorative copies are `aria-hidden`.

## 9. Open questions and notes

- **VFS names.** `SanitizeFilename` turns “Dune: Part Two” into “Dune- Part Two” (colon → hyphen without a space), which shows up in the WebDAV paths the UI displays. Consider mapping `": "` to `" - "`; it only affects new folders (existing paths must stay stable, see PLAN §10).
- **Artwork.** The prototype uses generated placeholder art in TMDB proportions (2:3 posters, 16:9 backdrops and stills, circular cast photos) in many colours to prove legibility over any art. Real TMDB images drop into the same slots (`Poster`, `Backdrop`, `Still` with the same aspect ratios and an ink 8 % inner hairline).
- **Momo.** The poses are production-ready vectors with theme-aware colours; a hand-drawn pass by an illustrator could add texture later without changing any layout.
- **Mapping flow timing** in the prototype is simulated (about 1 s per step).
